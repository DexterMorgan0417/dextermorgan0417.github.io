例子

PHP中的数组按照2^n的空间预先申请
引擎内部可以理解成：

  1. 拿到数组元素区的起始地址 arr_base
  2. 算出 $array[0] 的地址 elem_addr
  3. 读出旧值 elem
  4. 检查右边的 $var check_var() ← 这里可能插进 PHP 代码
  5. res = elem + var
  6. 把 res 写回 elem_addr ← 仍用第 2 步的旧指针

问题就在第 4 步。$var 未定义时，VM 不能把 “undefined” 直接交给用户代码，要报 Notice，并把变量变成
null。你注册了 set_error_handler，Notice 不会立刻结束，而是 在这条 opcode 还没写回时，先跑你的
PHP 回调。

回调里 $array[] = 2 会让数组扩容。PHP 数组按 2 的幂预分配，8 个元素再加 1 个就要 realloc。旧的元
素区被释放，新数组搬到别处。回调返回后，第 6 步还拿着旧 elem_addr 去写 → Use-After-Free。

作者把这种副作用叫 clobbering the world：后面的写回，不能再信任前面算出来的指针。
第一层：PHP 7 起 zend_array 的元素是一块连续内存。扩容只能 realloc，系统不保证地址不变。这是鸟哥
2020 年讲 HashTable 时留下的老问题。

第二层：赋值在 IR 里被拆成多条 opcode。比如：

$array[‘a’][‘b’] = $var;

会变成类似：

V2 = FETCH_DIM_W $array, “a” // V2 是指向 $array[‘a’] 的内部指针
ASSIGN_DIM V2, “b”
OP_DATA $var

就算你把 check_var 提前，FETCH_DIM_W 已经把中间指针 V2 算出来了。后面求值一旦让数组扩容，V2 同样
悬空。对象属性赋值也有同类问题。所以作者和 PHP 开发者都说这是 fundamentally hard：不是改一个
handler 就能收干净。

php前置知识

zval 结构

PHP中的变量都是以zval 的形式出现的，它是一个tagged union形式:

zval 永远是 16 字节

PHP 的 $a、$array[0]、函数参数，底层都是 zval，不是 C 的 int / char*。

zval（16 字节，x86-64）
┌─────────────────┬────────────┬────────────┐
│ value 8 字节 │ u1 4 字节 │ u2 4 字节 │
│ zend_value │ type_info │ 额外用途 │
└─────────────────┴────────────┴────────────┘

  • value：真正的数据，或指向堆上对象的指针
  • u1：类型（这是 long 还是 string）
  • u2：不是值的一部分，数组碰撞链、foreach 位置等拿来复用

Packed and Mixed Array

PHP中两种类型的数组:

  1. packed array : 用整数作为index连续存放的数组 i.e., $arr = [1,2,3,4];
  2. mixed array: 混合了以字符串以index作为的数组 i.e., $arr = [1, 'key1' => 'val1'];

Variable Assignment

这里讲一下两个zval *var, *val之间的赋值过程，它对应Zend/zend_execute.h中两个函数zend_assign_to_variable 和 zend_copy_to_variabl部分过程 。我用伪代码表示，因为适合突出一些重要的东西，并省略一些不太重要的信息。

它对应的两个函数明显会比我给出的伪代码复杂，但是我们不需要关注里面大多数cases。其中我们说一个zval是refcounted，意味它对应值需要额外分配内存，比如string， array和 object这些都是，而null，false， true，long 和double它们不是refcounted，因为它们的值是直接保存在zval中的。这里赋值过程的核心逻辑是我们特别需要注意var原本的值。

我来解释一下这里在做什么:

  1. 当var是refcounted时，我们做以下操作:
    1. 首先我们用var_value记录了var的原值;
    2. 我们直接通过copy_zval将val拷贝到var上;
    3. 判断var的原值的引用计数是否为1，如果是1则释放掉var的原值。
  2. 反之，我们直接通过copy_zval将val拷贝到var。

在1.3中var的原值的引用计数为1，意味着这个值只有var来用，当var被赋予新值之后，它的原值就没人用了，那么是可以释放掉的。其中copy_zval做了两件事情:

  1. 将val的值直接拷贝到var上;
  2. 按情况调整val所指向值的引用计数。 ?

copy_zval 两件事

  1. 把 val 的 16 字节拷到 var（类型、指针/整数一起过去）。
  2. 若新值是 string/array，通常 refcount++，因为又多了一个槽指着它。

例子
$a = “hello”; // var 指向字符串，refcount=1
$a = 1; // 槽改成 IS_LONG=1，”hello” 没人要了 → free

$a = “hello”;
$b = $a; // 同一块 zend_string，refcount=2
$a = 1; // 只改 $a 的槽；refcount 还剩 1（$b 还在用）→ 不能 free

Copy on Write

$a = ‘aaaa’; // 堆上一块 zend_string “aaaa”，refcount = 1
$b = $a; // 不拷字符。$b 的 zval 抄 $a 的指针，refcount = 2
echo $b; // 只读，还是同一块
$b .= ‘b’; // 要改 $b 了：发现 refcount > 1，先复制再改
echo $b; // $b 是 “aaaab”，$a 仍是 “aaaa”

内存：

第 1 行
$a ──► zend_string “aaaa” rc=1

第 2 行 $b = $a
$a ──► zend_string “aaaa” rc=2
$b ──┘

第 4 行 $b .= ‘b’ （rc>1，不能原地改，否则 $a 也会变）
$a ──► “aaaa” rc=1
$b ──► 新的 “aaaab” rc=1
怎么判断要不要复制

就看你要改的那块，refcount 是不是大于 1：

  • == 1：只有你在用，原地改（”aaaa” 后面直接接 “b”，或数组直接改元素）

  • 1：别人还指着它。先新分配，把内容拷过去，自己的 zval 改指新对象，旧对象 refcount–，再改新的

文章说「很简单」，判断式就是：

if (refcount > 1)
复制一份，让自己独占（新对象 rc=1）
然后再修改
