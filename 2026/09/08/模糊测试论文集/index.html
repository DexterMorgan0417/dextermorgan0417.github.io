Attention Distance: A Novel Metric for Directed Fuzzing with Large Language Models

  • 会议：ICSE 2026
  • 方向：LLM + Directed Fuzzing

核心问题

传统 Directed Fuzzing 通常使用 CFG 上的距离衡量当前执行路径与 Target 的距离，但控制流距离近不代表语义上容易到达 Target。
现有方法只衡量 seed 执行路径与 target 位置之间的物理距离，却忽略了代码片段之间的逻辑关系
许多分支的距离都差不多,出现Distance Collapse temporary blindness
例子(aflgo)

尽管某些分支的距离值相同,但仅有部分分支才能触发目标漏洞

核心思想与方法

利用 Large Language Model (LLM) 理解程序代码的语义，并构造一种 Attention Distance，衡量程序位置与 Target 之间的语义相关性。

用LLM来微调传统的CFG距离

技术抓手

  • LLM

  • Code semantic representation

  • Attention / semantic distance

  • Directed fuzzing guidance

使用一个针对 directed fuzzing 任务微调的轻量级 LLM，为每条程序语句计算 attention weight，然后将这些权重聚合成细粒度的 distance guidance
模型架构基于 CodeBERT，并采用 LineVul 的预训练/微调方法

存在的问题

spurious attention peaks
LLM Attention 很高 -> 但实际上和漏洞无关

Locus: Agentic Predicates Reasoning for Directed Fuzzing

  • 会议：ICSE 2026
  • 方向：Agent / LLM + Directed Fuzzing

核心问题

传统 Directed Fuzzing 通常把 Target 看成一个代码位置，但真正到达 Target 往往需要满足一系列 Predicates / Conditions。
有点类似beacon提前剪枝
程序本身的结构不会很好的反馈 fuzzer的条件与最终条件的差距
程序真正要求的状态存在，但代码里没有足够的 predicate 可以让 fuzzer 感知“我已经接近了

核心方法

利用 LLM Agent 对程序和 Target 进行推理，识别到达 Target 所需要满足的中间 predicates，然后利用这些 predicates 指导 fuzzing。

从目标程序状态一直推理到输入，通常需要非常长的上下文和复杂的分析链
Locus 将约束生成从输入层扩展到了任意程序位置
一个程序 predicate φ 是从程序状态空间到 True/False 的布尔映射
自动发现“原程序没有显式表达，但对于到达漏洞非常重要”的 Boolean condition

Locus = LLM Agent 自动分析漏洞目标，合成一组位于程序中间位置的 Predicate，再经过编译器和 Symbolic Execution 验证，最后把 Predicate 插入程序作为新的 fuzzing feedback

核心思想

从“如何走到 Target”转变为“如何逐步满足到达 Target 所需的条件”。

8. Variability-Aware Fuzzing

  • 会议：ICSE 2026

  • 系统：VAFuzz

  • 方向：Configuration-Aware Fuzzing

核心问题

可配置软件存在巨大的 Configuration Space。

配置数量可能呈指数增长。

传统 Fuzzing 主要探索 Data Input Space，忽略了 Configuration Space。

核心方法

同时探索：

通过 Presence Conditions 判断哪些 configuration 更值得探索，并记录不同 configuration 下有效的 Data Seeds。

技术抓手

  • Variability analysis

  • Presence conditions

  • Configuration scheduling

  • Data-seed association

  • Runtime feedback

  • AFL++

核心思想

将 Configuration Space 纳入 fuzzing feedback loop，而不是在 fuzzing 前静态枚举配置。

总结

这些论文的共同趋势是：

Fuzzing 正从“随机修改输入 + Coverage Feedback”逐渐转向“理解程序状态、条件、输入结构和配置空间，再进行有目的的搜索”。
