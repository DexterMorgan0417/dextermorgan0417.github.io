DFM

项目概述

作为AFL的c++重构,保留了基本的结构,但也做了一定的修改

架构设计

由DFM主类协调各模块

DFM

模糊测试主类,用于协调各个模块工作

ForkServerManager

forkserver管理器,管理多个forkserver以提高进程并发效率

monitor

变异器,只负责接收相关信息并对数据变异

FuzzDriver

fuzzdriver是模糊测试的执行器,负责将变异后的数据送入目标进程,并收集目标进程相关信息

ICorpus

语料库抽象接口,负责管理种子池并去重

Sampler

采样器抽象类,负责维护自身选择的种子队列,并为driver提供种子,并接受相关信息,以及选择变异算法.

Cirilla

DGF策略模块,基于调用树,支持多目标区分和协同

Idea

读感知

AFL不做对目标程序的读感知,导致对于需要多次交互程序效率极低.

linux 读类型的系统调用

技术实现

eBPF

缺点,捕获所有系统调用.

seccomp user notification

目标程序执行被监控的系统调用时会暂停,

传递文件描述符方法

目标进程插桩,传递它的seccomp_notif_fd给模糊器,模糊器依靠这个fd拦截目标相关系统调用,并传递输入向量.

传递文件描述符

版本1,通过抽象命名空间进行传递

接收端创建 AF_UNIX 类型的 socket，bind 到与发送端相同的地址（可以是文件路径或抽象命名空间）。抽象命名空间在 sockaddr_un.sun_path[0] = ‘\0’ 并且 bind 时传入的长度需按 offsetof 计算（包含前导 NUL）。

对于 SOCK_SEQPACKET/STREAM，调用 listen/accept。accept 返回连接 socket 用于 recvmsg。
使用 recvmsg()，把 msg_control 指向一个足够大的缓冲区（CMSG_SPACE(sizeof(int))）；成功后用 CMSG_FIRSTHDR / CMSG_NXTHDR 查找 cmsg_level SOL_SOCKET && cmsg_type SCM_RIGHTS，从 CMSG_DATA(cmsg) 读取整型文件描述符。

建议在接收后用 getsockopt(…, SO_PEERCRED) 校验对端 UID/PID（安全性），并根据需要对接收到的 fd 设置 close-on-exec 标志或其它选项。
处理 EINTR、msg 长度为 0、ancillary 数据缺失等边界情况。

读写目标进程

使用process_vm_readv/writev 不需要ptrace, 防止目标进程存在反调试代码.
