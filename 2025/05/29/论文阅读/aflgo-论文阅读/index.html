摘要

现有的灰盒模糊测试无法有效地定向测试,

此文介绍了定向灰盒模糊测试 Directed Greybox Fuzzing (DGF),旨在高效生成能够到达给定目标程序位置的输入.开发并评估了一种基于模拟退火的能量调度策略，该策略逐渐为接近目标位置的种子分配更多能量，同时减少远离目标的种子的能量.

根据实验表明,AFLGo表现好于基于符号执行的白盒模糊测试和非定向的灰盒模糊测试.AFLgo在LibXML2等项目中发现了39个bug,17个被分配了CVE.

DFG将大部分时间用于到达指定位置中,不在别处浪费时间

应用包括

  • 补丁测试 将变化的代码部分作为目标,检查更新是否引入漏洞
  • 漏洞复现 通过堆栈跟踪函数链作为目标
  • 静态分析报告验证 标记静态分析报告的危险代码,测试漏洞是否存在
  • 信息流检测 标记数据流,追踪传播路径(???)

现有的定向模糊测试大多依赖于符号执行

定向符号执行将路径是否可达转化为迭代约束满足问题(ICSP)

ICSP:

ICSP是传统约束满足(CSP)的扩展

传统CSP要求一次性求解所有的变量以满足全部约束,变量过多或约束条件负责时导致组合爆炸

ICSP 将问题拆分为多个子约束集,逐步迭代到达最终状态

由于大多数路径实际不可达,搜索通常寻找中间路径来迭代进行.

DES(Directed symbolicexecution)需要消耗大量时间在约束求解上,相比GF效率低下.

在相同的初始种子下,AFLgo比Katch快不少,不足20分钟找到了心脏滴血漏洞

本文提出定向灰盒模糊测试DGF,聚焦道道给定的目标位置,从宏观层面使用元启发式算法最小化种子与目标位置的距离

为计算这个距离,对每个基本块到目标的距离进行计算与插桩

尽管种子距离是跨过程的(???),新度量方法仅对调用图和CFG分析一次

运行的时候计算每个已经执行的基本块的距离,为种子计算这些值的均值

本工具使用模拟退火算法作为元启发式算法,并使用能量调度实现.

将分析移至编译阶段,减小了运行时开销

代码分析

过程简述

1.编译并插桩目标以产生日志与 dot 文件
用 aflgo-clang / aflgo-clang++（由 aflgo-clang.c）编译目标，加载 LLVM 插件 aflgo-pass.so.cc。
插桩过程输出：dot-files/cfg..dot、BBnames.txt、BBcalls.txt、Fnames.txt、Ftargets.txt（写入到指定临时目录）。

2.生成并合并 Call-Graph（CG）
使用 LLVM opt -dot-callgraph（脚本封装在 gen_distance_orig.sh 或 gen_distance_fast.py 的 opt_callgraph）为编译产物生成 callgraph.dot，若有多二进制则合并多个 callgraph。

3.计算 Call-Graph 层面的距离（可选先行）
调用距离计算器（默认优先 distance/distance_calculator/distance.bin，或 Python 版 distance.py）对 callgraph.dot 与 Ftargets.txt/Fnames.txt 计算 CG 距离，输出如 distance.callgraph.txt（或 callgraph.distance.txt）

4.逐函数计算 CFG 层面的距离（并行化常用）
对每个 cfg..dot 调用距离计算器（distance.bin/distance.py），结合 BBtargets.txt、BBnames.txt、BBcalls.txt 和上一步的 CG 距离，输出每个函数对应的 cfg..distances.txt。

5.合并所有 CFG 距离文件到单个 distance 配置
将所有 *.distances.txt 合并为最终文件，例如 distance.cfg.txt（gen_distance_fast.py / gen_distance_orig.sh 会做此步）。

6.用 distance 文件重新编译以注入 distance 信息（可选选择性插桩）
重新用 aflgo-clang 并传 -distance=$(readlink -e/distance.cfg.txt)，aflgo-pass 会读取并在插桩中使用每个 basic block 的距离数值。

7.用 AFL 进行定向模糊（Directed Fuzzing）
用重编译后的二进制配合 afl-2.57b/afl-fuzz 启动定向模糊，距离信息会影响 power schedule / 优先级。

与AFL区别

距离bitmap

在原有的bitmap后门追加一块额外的槽,用于存放distance的整型值

每次执行到具有distance的BB,就会把distance加到对于的位置,这个位置是和原有生成的hash值是一致的

再后面有个槽位存储计数器的值

distance文件夹

en_distance_fast.py

作用：并行化/驱动脚本，组织生成 call-graph/CFG、拆分任务并调用实际的距离计算程序（Python 或 C++ 二进制），然后合并结果。是主流程的调度器。
输入：preprocessing 生成的 BBnames.txt/BBcalls.txt/Ftargets.txt 等（以及编译生成的 callgraph/CFG 文件）。
输出：合并后的距离文件（供 instrument/aflgo-pass.so.cc -distance 使用）。
依赖：会调用 distance_calculator 下的脚本/二进制、shell 工具，可能需要并行工具/Python 环境。
gen_distance_orig.sh

作用：早期的单进程/串行 distance 计算流程脚本（慢版），保留作参考或快速小规模测试。
输入/输出：与 fast 脚本相同，但不并行。
add_edges.py

作用：处理/修补 call-graph/CFG 数据的辅助脚本（如把某些调用关系加入图），用于生成更完整的图供距离计算。
用途：在生成的 callgraph 有遗漏或需要合并手工信息时使用。
merge_callgraphs.py

作用：把多个子任务/分片产生的 callgraph/CFG 信息合并成全局图，为后续距离计算提供完整视图。
用途：配合 gen_distance_fast.py 的分片并行输出合并结果。
子目录：distance_calculator/

distance.py

作用：纯 Python 实现的距离计算器（通常基于 NetworkX 或自实现的图算法），读取 callgraph/CFG，计算从每个基本块到目标集/目标点的最短距离（或自定义距离度量），输出每个 BB 的 distance。
优点：易读、便于修改；缺点：对大项目可能慢（单线程 Python）。
依赖：Python、NetworkX（若使用）或标准 Python 库。
distance.bin.cc

作用：C++ 实现的高性能距离计算器（通常使用 Boost Graph 或自实现图算法），编译为二进制 distance.bin，用于在大规模项目上快速计算距离。
优点：速度快、适合并行/批量运行；缺点：需编译（CMake）。
依赖：Boost/编译链，CMakeLists.txt 提供构建规则。
CMakeLists.txt

作用：构建 distance.bin.cc（生成可执行二进制）的 CMake 配置。
其它

.clang-format
作用：代码风格配置（用于 distance_calculator 源代码的格式化）。

距离计算

用最短路径（Dijkstra）按 1/(1+dist) 的倒数加权并做归一化，得到“距离值”；CFG 模式还会结合 CG 层给出的函数级距离（带 10 倍因子）；最终插桩端把该浮点值乘 100 存为整数。

aflgo-pass.so.cc

两个模式

预处理, 由-targets -outdir 触发,遍历模块,导出函数CFG,记录 basic-block 名单、callsite 映射、函数名与目标函数列表，供后续的distance插计算使用；

distance 插桩模式（由 -distance触发）——读取 distance 文件并在每个 basic block 的 IR 中注入运行时逻辑，把 distance 值累加到 AFL 的共享内存（SHM）特定槽位，从而在 fuzz 时被利用为 directed-fuzz 的信号。
