Call Tree (CT，调用树)
描述一次具体程序执行（或单线程的一次运行）中按调用/返回关系展开的树。每次函数调用对应一个节点（对应一个栈帧实例）。节点可以重复出现（递归产生多个不同栈帧节点）。CT 是时间序列的嵌套展开，严格反映那次运行的实际调用序列。
Calling Context Tree (CCT，调用上下文树，又称 Call Path Tree)
把运行时观察到的所有调用路径按调用上下文组织成的一棵树。CCT 的每个节点代表“在某个调用路径下到达某函数”的上下文（即从程序入口到当前调用的调用序列）。相同的调用上下文合并为同一节点，节点通常带有聚合信息（调用次数、耗时等）。

br 分支（BranchInst）

无条件分支：br label %dest
条件分支：br i1 %cond, label %then, label %else
这是最常见的 CFG 边来源。
switch 多路分支（SwitchInst）

switch i32 %x, label %default [ i32 0, label %case0 … ]
产生多条 successor 边：default + 各 case。
indirectbr 间接分支（IndirectBrInst）

indirectbr i8* %addr, [label %L1, label %L2, …]
目标地址运行时决定（从地址跳转），常见于跳转表/异常化实现/特定优化。
invoke（InvokeInst）与异常边

invoke 同时有 正常返回目标 和 异常目标（landingpad） 两条 CFG 边：
normal dest
unwind dest
如果你做 BB 图，不能只看 br/switch，否则会漏异常控制流。
callbr（CallBrInst）

用于 GNU asm goto 这类场景：除了正常返回块外，还有一组“间接跳转目标”基本块。
也是多 successor。
ret 返回（ReturnInst）

终结当前函数控制流（没有 successor）。
但在跨过程分析里，常被建模成“返回到调用点继续执行”的跨过程边（这不是 IR 自带 CFG 边，是你分析建的边）。
resume / catchswitch / catchret / cleanupret（异常处理相关终结指令）

这些属于异常控制流终结指令体系（尤其 Windows SEH / Itanium EH lowering）。
如果你分析要覆盖异常路径，需要把它们的 successor 也纳入图。
unreachable

表示不可达终点（无 successor），但会影响 CFG（例如某些分支到这里）。

ICFG提供的信息

节点
BasicBlock（或可选择折叠到 Function/BB-id）：每个 BB 唯一标识并保留指向其 Function。
边（有向）
CFG 边：BB -> successor(BB)（来自 br/switch/indirectbr/invoke 等 terminator 的后继）。
Call 边：callsite_BB -> callee_entry_BB（直接调用可精确解析）。
Return 边：callee_return_BB -> callsite_continuation_BB（把调用与返回连成闭环，识别跨函数循环必需）。
Exception/Unwind 边：invoke 的 unwind dest、resume/catch 等（如需异常流）。
边属性（metadata）
EdgeKind：{CFG, Call, Return, Exception, Other}。
viaInst：产生该边的 Instruction*（用于获取 DebugLoc、打印 callsite）。
条件信息：对于条件 br 标注 true/false；switch 标注 case value / default。
源/目标的 DebugLoc（便于打印 file:line）。
可选权重/热度（来自 profile sampling 或运行时 trace）。

污点分析

精确/模糊 原始字节序列与相关变量是否有关,再根据静态分析结果来精确到某些序列的确定值

传统的污点分析:

污点分析可以抽象成一个三元组<sources, sinks, sanitizers>的形式。sources：污点源，代表直接引入不受信任的数据或者机密数据到系统中。sink：污点汇聚点，代表直接产生安全敏感操作或者泄露隐私数据到外界。sanitizer：无害处理，代表通过数据加密或者移除危害操作等手段使数据传播不再对软件系统的信息安全产生危害

污点分析模型

原始字节序列 作为目标程序的输入,是一串有一定长度的二进制序列,没有任何限制.称为初始输入向量(original input vector)

反向传播

沿着直接跳转边进行反向传播,而非条件分支跳转.且不考虑间接调用情况(加剧考虑情况,不一定更号)

理论：从 exit 基本块开始做反向图遍历，但只穿越那些以无条件分支连接的边；在每个访问到的基本块内检测“写返回值”和“副作用”指令，若发现副作用则记录并停止进一步回溯该路径。
目标产物：一个函数（例如 collectSourcesForExit(BB)）返回每个“来源 BB”的信息：{BB*, isWriteReturn, isSideEffecting, DebugLoc}。

存在的问题

若某些函数/BB 虽然会退出进程/线程,但是也完成了某些重要功能,这种情况下是否要保留还是进一步分析

算法步骤

  1. 使用LLVM提供的CG图,遍历每个节点,存储调用映射 <caller,callees>
  2. 遍历TargetFunction 加入BackwardFunctions 和工作队列中,并标记函数已经处理
  3. 遍历队列
  4. 取出队头函数,并基于1获取的信息得到所有调用者,如果没有调用者则重复当前步骤
  5. 遍历调用者,过滤LLVM内部函数.如果该函数没有被处理过,加入到BackwardFunctions 和队尾.

算法缺陷:

LLVM CG未包含间接调用情况,算法会被间接调用中断传播

仅标记函数是否处理来避免循环爆炸,会出现遗漏情况.例如 A->B-C D->B->C. A D必有一个被丢弃
