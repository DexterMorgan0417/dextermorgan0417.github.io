EMS

1. Abstract (摘要)

  • 核心问题： 基于变异的模糊测试（Mutation-based Fuzzing）因其变异过程的高随机性而效率低下。现有的覆盖导向模糊测试（Coverage-based Fuzzing）解决方案（如自适应变异策略、约束求解集成）缺乏对历史模糊测试数据（fuzzing history）的细粒度重用，未能有效利用不同模糊测试进程（intra/inter-trial）中的知识。

  • 核心发现： 历史测试用例中包含导致发现独特路径和崩溃的关键变异策略知识。这些策略隐含地携带了部分路径约束（partial path constraints）的解决方案，可用于加速发现具有相似约束的新路径和崩溃。

  • 解决方案： 提出**PBOM (Probabilistic Byte Orientation Model)**：一种轻量级、高效的模型，用于从历史数据（intra/inter-trial）中捕获字节级的变异策略。

  • 框架： 提出**EMS (History-Driven Mutation Framework)**：利用PBOM作为变异算子（mutation operator），根据输入字节值概率性地提供所需的变异字节值和变异类型。

  • 评估：

    在9个真实程序上评估EMS，对比AFL, QSYM, MOPT, MOPT-dict, EcoFuzz, AFL++。结果显示：

    • EMS发现比基线（AFL）多4.91倍的独特漏洞（unique vulnerabilities）。
    • 在大多数程序上，EMS发现比其他模糊器更多的行覆盖率（line coverage）。
    • 报告了所有新发现的漏洞，并将开源EMS。

  • 主要贡献：

    • 发现历史数据中蕴含关键变异策略知识。
    • 提出轻量高效的PBOM模型。
    • 提出并实现EMS框架。
    • 广泛评估证明EMS在漏洞发现和覆盖率上的优越性。
    • 报告漏洞并开源。

2. I. INTRODUCTION (引言)

  • 背景与挑战： 重申模糊测试的重要性，指出传统变异模糊测试的随机性导致效率低下。覆盖导向模糊测试（如AFL）通过探索独特执行路径来改进，但仍存在不足。现有改进工作（自适应策略如AFLFast/EcoFuzz，约束求解集成如QSYM/Angora，机器学习引导如Augmented-AFL）未能充分利用历史数据（特别是跨进程历史）。

  • 核心洞察： 历史测试用例中的变异策略（从种子到触发独特路径的变异体）可能包含共同策略（如解决特定分支行为的约束），这些策略可被重用。软件开发的复用实践（共享库、函数、逻辑）支持了这一洞察。

3. II. BACKGROUND (背景)

  • A. Mutation-based Fuzzing (基于变异的模糊测试): 介绍基本工作流程：初始种子集 -> 种子队列 -> 选择种子 -> 随机变异 -> 测试程序 -> 添加有趣测试用例（触发新路径/崩溃）回队列 -> 循环。以AFL为例说明其变异阶段（确定性阶段 deterministic stage，混乱阶段 havoc stage，拼接阶段 splicing stage）。指出其优点是执行速度快，缺点是难以解决复杂路径约束。

  • B. Coverage-based Fuzzing (基于覆盖的模糊测试):

    介绍利用覆盖率反馈改进模糊测试的方向：

    • 自适应策略改进种子选择/生成： 如AFLFast（马尔可夫链评估种子潜力），EcoFuzz（对抗多臂老虎机模型），MOPT（自适应优化变异算子选择概率）。
    • 集成约束求解技术： 如QSYM（快速concolic执行引擎），Angora（梯度下降代替concolic执行）。指出约束求解成本高。
    • 机器学习定位关键字节： 如Augmented-AFL（神经网络预测关键位置），NEUZZ（神经网络学习分支行为+梯度引导定位关键字节）。指出这些方法通常需要先运行AFL获取训练数据。

  • 总结与问题： 现有覆盖导向模糊器主要关注更好地探索测试用例空间，但缺乏对历史数据（特别是intra-trial历史）的充分利用，且未利用过往实验（inter-trial历史）的结果。

4. III. DESIGN OF EMS (EMS的设计)

  • A. Why Intra- and Inter-Trial History Matters (为什么历史数据重要): 深入阐述引言中的动机。现有模糊器（如MOPT, EcoFuzz）考虑了intra-trial历史的高层启发式信息（种子选择），但缺乏对触发独特路径/崩溃的具体变异策略的细粒度重用。程序不同路径可能调用相同函数或包含常见值（如-1,0,1, magic bytes, checksums）。跨程序（同厂商或使用相同库）也存在共享代码和约束。因此，历史数据中的高效策略可被总结和复用。

  • B. Framework of EMS (EMS框架):

    • 目标： 学习历史数据中导致独特分支行为的变异策略，根据输入字节值提供高效变异策略，解决计算成本和速度挑战。

    • 符号定义： 明确定义输入字节值 in 及长度 L，变异算子 (out, type)，输入字节值集合 IN，变异策略集合 MO，概率输出策略 (out, type, F, P)，策略集合 T，偏好位置列表 favorite_list，Inter-PBOM, Intra-PBOM。

    • 框架图 (图 3) 与工作流程：

      • Inter-PBOM Initialization (Inter-PBOM初始化): 在模糊测试开始时构建Inter-PBOM。步骤：提取历史数据中的 in 和 MO -> 统计每个 (out, type) 的频率 F -> 计算选择概率 P (公式1: P_i ∝ 1 - F_i / ΣF_k) -> 构建哈希映射 (in -> (out, type, F, P))。

      • PBOM Operator (PBOM算子):

        在确定性阶段（Deterministic Stage）和混乱阶段（Havoc Stage）使用PBOMs作为变异算子。

        • 确定性阶段： 仅使用Inter-PBOM（因Intra-PBOM初始为空）。随机选择位置读取 in -> 在PBOM中搜索匹配 -> 对每个匹配的 (out, type) 应用一次变异 -> 测试 -> 恢复原状 -> 尝试下一个策略。
        • 混乱阶段： Inter/Intra-PBOM作为两个算子，由粒子群优化算法决定选择概率。选择PBOM算子后：选择长度 L -> 选择位置（小概率选 favorite_list，大概率随机）-> 读取 in -> 在PBOM中搜索匹配 -> 根据概率 P 选择一个 (out, type) -> 应用变异。

      • Operator Analysis and Data Collection (算子分析与数据收集): 记录每次变异（包括传统算子和PBOM算子）的 in, type, out, 位置。如果变异后的测试用例触发新路径或崩溃，则记录的数据被视为高效策略，用于后续更新Intra-PBOM。

      • Intra-PBOM Update (Intra-PBOM更新): 定期使用新收集的高效策略更新Intra-PBOM。构建过程类似Inter-PBOM初始化，但概率计算使用公式2 (P_i = F_i / ΣF_k)，即频率越高，选择概率越大。

    • Inter-PBOM概率算法 (公式1): P_i = (Σcount((out_k, type)) - count((out_i, type))) / ((n-1) * Σcount((out_k, type)))。核心： 为频率 F 较低的 (out, type) 分配更高的选择概率 P。鼓励探索历史中较少出现的（可能更复杂或针对特定约束的）变异策略。

    • Intra-PBOM概率算法 (公式2): P_i = count((out_i, type)) / Σcount((out_k, type))。核心： 为频率 F 较高的 (out, type) 分配更高的选择概率 P。鼓励重用当前测试进程中已被证明有效的变异策略。

5. IV. IMPLEMENTATION OF EMS (EMS的实现)

  • 基础： 基于MOPT实现EMS。
  • PBOM算子集成： 将PBOM算子集成到MOPT的确定性阶段和混乱阶段（拼接阶段后进入混乱阶段，故无需在拼接阶段集成）。
  • Inter-PBOM初始化细节： 使用MOPT模糊 pdfimages 5小时收集初始训练数据（137,337条高效策略，43,758个独特 in），构建Inter-PBOM耗时9秒。
  • 运行时： 开始模糊目标程序时加载Inter-PBOM。在模糊过程中，使用Operator Analysis收集高效策略，并定期更新Intra-PBOM。

7. VI. FURTHER ANALYSIS (进一步分析)

- 

A. PBOM Contribution Analysis (PBOM贡献分析):



- **方法：** 实现定制版EMS（EMS-test），移除PBOM算子的变异，比较原始测试用例与其“影子”版本（仅含传统算子变异）触发的漏洞和边缘覆盖率。

- 

    结果 (表 VI):

    

    - PBOM算子贡献了额外的独特漏洞发现（在部分试验中，移除PBOM后影子版本无法触发某些漏洞）。
    - PBOM算子显著提高了边缘覆盖率（平均提升约28%）。

- **结论：** PBOM算子提供了触发更多漏洞和覆盖的关键变异。

- 

B. Efficient Mutation Strategy Analysis (高效变异策略分析):



- 

    跨程序策略复用 (表 VII):

     分析不同程序间高效策略的相似性。

    - 相同策略的比例不可忽视（例如，`pdfimages` 的策略有60%以上也适用于 `nasm`）。
    - 大量策略通过变异相同的 `in` 值触发不同程序的独特路径/崩溃（`Nn1` 和 `Ny` 占比高）。

- 

    同程序不同时长策略复用 (表 VIII):

     分析同一程序不同模糊时长收集策略的相似性。

    - 相同策略占主导（`Ny` 占比高，例如 `pdfimages` 7天结果与之前结果有66.4%相同）。

- **结论：** 验证了Inter-PBOM的有效性基础——历史策略可在同程序或不同程序（尤其同厂商）间复用。

- 

C. Algorithm Overhead Analysis (算法开销分析):



- **方法：** 对比EMS和MOPT在仅执行混乱阶段变异时的总执行次数（控制变异时间和测试用例执行影响）。
- **结果 (表 IX):** EMS的平均执行次数比MOPT低约3.04%，执行速度略有下降（~547.31次/秒 vs. ~564.47次/秒）。
- **结论：** EMS的开销（源于变异过程、数据收集、PBOM微调）在可接受范围内，其带来的漏洞和覆盖提升远超此微小速度损失。

-

- 

    结果 (图 13, 图 14):

8. VII. DISCUSSION AND LIMITATION (讨论与限制)

  • A. Mutation Operator Development (变异算子开发): 建议未来可将高效策略按类型（如触发特定漏洞、触发稀有路径）分类，构建更细粒度的算子。
  • B. Mutation Location Selection (变异位置选择): 当前使用 favorite_list 指导位置选择。未来可探索基于历史数据更细粒度地分析位置对特定分支行为的影响。
  • C. Application of Machine Learning Algorithms (机器学习算法的应用): 尝试过seq2seq模型，虽在部分程序有效，但计算开销大导致速度慢。结论：频繁调用的变异算子不适合复杂ML模型（速度瓶颈），但在高延迟目标（如服务）上可能有潜力。
  • 限制 (Limitation): 未明确列出独立章节，但讨论中隐含：PBOM模型相对简单；跨程序策略复用依赖于程序间的逻辑/库共享；更细粒度的策略分类和位置选择是未来方向。

9. VIII. RELATED WORK (相关工作)

  • A. Mutation-based Fuzzing (基于变异的模糊测试): 回顾AFL及其改进工作（AFLFast, EcoFuzz - 能量分配；MOPT - 算子调度）。
  • B. Generation-based Fuzzing (基于生成的模糊测试): 提及利用语法/语义规则生成测试用例的方法（Skyfire, Nautilus, Montage），与EMS的变异基础不同。
  • C. Machine Learning-based Fuzzing (基于机器学习的模糊测试): 提及利用ML定位关键字节（Augmented-AFL, NEUZZ）或生成输入（Learn&Fuzz），指出其通常依赖初始模糊运行或计算开销较大。
  • D. Other Fuzzing Strategies (其他模糊测试策略): 提及种子集优化、评估指标、内核模糊测试、定向模糊测试、反模糊测试防护等其他研究方向。
  • 与EMS的区别： 强调EMS的核心创新点是细粒度地学习和重用历史模糊测试数据中的具体字节级变异策略（通过PBOM模型），这是现有工作所缺乏的。

10. IX. CONCLUSION (结论)

  • 重申核心发现： 历史模糊测试数据（intra/inter-trial）蕴含导致独特路径和崩溃的关键变异策略知识。
  • 重申解决方案： 提出轻量高效的PBOM模型捕获这些策略；提出并实现EMS框架将PBOM作为变异算子集成。
  • 重申评估结果： 在9个真实程序和FuzzBench上广泛评估，证明EMS在发现独特漏洞（比AFL多4.91倍）和行覆盖率上显著优于最先进的模糊器。报告了所有新漏洞并开源。
  • 未来价值： EMS为改进基于变异的模糊测试的覆盖率和漏洞发现提供了新方向。
