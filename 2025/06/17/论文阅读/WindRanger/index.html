WindRanger

摘要

  • 内容： 介绍了论文的核心工作——WindRanger，一个由“偏差基本块”（Deviation Basic Blocks, DBBs）驱动的定向灰盒模糊器。摘要首先阐述了DGF的目标是引导模糊器到达程序中预定义的目标位置（如漏洞点、补丁代码），其关键在于评估种子输入的执行轨迹与目标位置的距离（种子距离）。现有方法（如AFLGo）基于控制流图计算所有执行基本块到目标的距离并求平均，存在两个主要问题：(1) 并非所有基本块对导向目标都同等重要，包含不重要的块会导致距离计算偏差；(2) 仅依赖控制流信息，忽略了数据流信息（如条件分支的满足难度）。WindRanger通过识别DBBs（执行轨迹开始偏离目标位置的关键基本块）来解决这些问题。它结合静态可达性分析和动态过滤来识别DBBs，并利用DBBs及其相关的数据流信息进行种子距离计算、变异、种子优先级排序以及探索-利用调度。在包含29个程序的3个数据集上的大规模实验（38,400 CPU小时）表明，WindRanger在到达目标位置方面比AFLGo、AFL和FAIRFuzz分别快21%、34%和37%，在检测目标崩溃方面分别快44%、66%和77%。此外，WindRanger通过在ffmpeg（一个被OSS-Fuzz广泛模糊测试的多媒体库）中设置手动识别的可疑位置作为目标，成功发现了一个0-day漏洞并获得CVE ID。

  1. 1 引言 (1 INTRODUCTION)

    内容：

    • 背景： 软件漏洞是软件安全的主要威胁。模糊测试（Fuzzing）是一种通过向被测程序（PUT）输入大量测试输入并观察异常行为（如崩溃）来发现漏洞的技术。根据对程序内部信息的利用程度，模糊测试可分为黑盒、灰盒和白盒。灰盒模糊测试使用轻量级程序插桩收集运行时信息，在有效性和可扩展性上取得了较好的平衡，被广泛采用。

    • 问题： 尽管灰盒模糊测试很有效，但它通常缺乏定向性（Directedness），即难以引导模糊器到达预定义的目标位置（目标站点）。定向灰盒模糊测试（DGF）旨在解决这个问题，将大部分时间预算用于到达和测试目标位置，而非最大化代码覆盖率。这使得DGF在补丁测试（目标=补丁代码）、崩溃复现（目标=崩溃点）和静态分析报告验证（目标=可疑位置）等场景中表现出色。

    • 挑战： 在这些场景中，时间预算有限且目标位置可能很多。因此，加速引导模糊器到达目标位置的过程至关重要。DGF的核心是识别和优先处理执行轨迹更接近目标的种子。因此，准确计算种子距离是关键。AFLGo提出了一种高效的两步法计算种子距离，但存在两个缺陷：(1) 使用所有执行基本块计算的平均距离可能因包含不重要的块而产生偏差；(2) 仅基于控制流信息（边数），忽略了数据流信息（如分支条件的满足难度）。

    • 解决方案与贡献： 通过分析未能到达目标的执行轨迹，作者观察到存在一些关键基本块（DBBs），在这些点上执行轨迹开始偏离目标。如果能在DBBs上改变执行路径，就有可能到达目标。基于此，论文提出了WindRanger，一个利用DBB信息增强的DGF工具。其主要贡献包括：(1) 提出DBB概念及识别方法；(2) 提出利用DBB信息增强种子调度和变异策略的WindRanger；(3) 实现了原型并开源代码；(4) 通过大量实验评估并证明了WindRanger的优越性。

    • 作用： 阐述研究背景、动机、现有工作的局限性，引出本文的核心问题和解决方案，并概述主要贡献。

  2. 2 动机示例 (2 MOTIVATING EXAMPLE)

    内容：

    使用一个基于CVE-2018-8962（Use-After-Free漏洞）的简化代码片段及其控制流图（CFG）作为示例。

    • 场景设定： 目标位置是触发漏洞的函数调用点（图1中行16和行22对应的基本块）。展示了三个种子（A, B, C）的执行轨迹。

      现有方法（AFLGo等）的问题

      • 种子C问题： 现有方法计算种子C的距离最小（2.0），应被优先选择。但实际上，种子C需要满足行15的一个非常困难的条件（如校验和匹配），极难穿透。这说明了仅依赖控制流信息（边数距离）的不足，需要数据流信息（条件难度）。

    • 种子A vs B问题： 现有方法计算种子B的距离（2.33）小于种子A（2.86），应优先B。但观察执行轨迹，种子A的轨迹实际上更接近目标（行22），因为种子A执行了距离目标很近的节点（行21:1），只是因为它也执行了一些距离目标较远的节点（行7:5, 9:4, 12:3）导致平均距离变大。这说明了使用所有基本块计算平均距离会产生偏差。

  • 观察与DBB概念： 对于未能到达目标的执行轨迹，必然在某些基本块处开始偏离目标。例如，种子A在节点21:1偏离（未进入if条件），种子B在节点20:2偏离，种子C在节点15:1偏离。这些点被称为偏差基本块（DBBs）。节点14:2不是DBB，因为它的两个后继都能到达目标。

    • 初步方案： 如果仅基于DBBs计算平均距离，种子A、B、C的距离分别为1、2、1。再结合数据流信息（调整种子C的难度），最终可以优先选择实际最优的种子A。识别DBBs是关键。

    • 识别DBBs的复杂性： 通过另一个种子D的例子说明，DBB不一定是距离目标最近的基本块，而是其执行路径选择了无法到达目标的后继节点（偏离点）。

    • 作用： 通过一个具体、直观的例子，清晰地说明现有DGF方法（如AFLGo）在种子距离计算上的两个核心缺陷（偏差问题和数据流缺失），并引出DBB的概念及其重要性，为理解WindRanger的设计动机奠定基础。

  1. 3 WindRanger的方法 (3 APPROACH OF WINDRANGER)

    内容：

    详细描述了WindRanger的设计与实现。图2展示了整体工作流程，包含两个主要组件：静态分析和模糊测试。

    3.1 偏差基本块识别 (Deviation Basic Blocks Identification):

    • 静态DBB收集： 定义了程序的潜在DBBs：一个基本块b是潜在DBB，当且仅当(1) b可达至少一个目标站点T；(2) b的至少一个后继c不可达任何目标站点。WindRanger通过构建过程间控制流图（iCFG）并计算每个基本块到目标的可达性来识别潜在DBBs。

    • 动态DBB收集： 定义了种子s的执行轨迹的DBBs：一个基本块b是s的DBB，当且仅当(1) b在s的执行轨迹ξ(s)中；(2) b是程序的潜在DBB；(3) b的所有可达后继（ReachableSuc(b)，指能到达目标的后继）都没有被s执行。WindRanger在执行过程中动态识别满足这些条件的DBBs。也就是种子s执行的过程中,命中的DDB.

    • 3.2 基于探测的污点分析 (Probing-based Taint Analysis): 类似于FAIRFuzz和GREYONE，WindRanger使用轻量级动态污点分析（称为“探测”）来收集数据流信息。它通过逐字节突变种子（位翻转、插入、删除）并观察比较约束变量值的变化，推断出哪些输入字节可以影响特定分支条件，结果存储在效应器映射（effector map） 中（键=分支基本块地址，值=影响该分支的输入字节索引集合）。该信息用于后续的种子距离微调和数据敏感变异。

    • 3.3 种子距离计算 (Seed Distance Calculation): WindRanger计算种子距离的核心公式是DBBs距离的平均值：d_s(s, T_b) = (Σ_{m∈Φ(s)} d_b(m, T_b)) / |Φ(s)|。这与AFLGo/Hawkeye公式结构相同，但关键区别在于仅使用DBBs Φ(s) 而非所有基本块。为了融入数据流信息，公式被调整为：d_s(s, T_b) = (Σ_{m∈Φ(s)} [d_b(m, T_b) * Ψ(s, m)]) / |Φ(s)|。其中 Ψ(s, m) 是难度调整因子，基于效应器映射计算影响DBB m 约束条件的输入字节数 NumOfEffectiveBytes(s, m)：Ψ(s, m) = min(Max_Ψ, ceil(NumOfEffectiveBytes(s, m) / γ)。γ 是控制粒度的常数，Max_Ψ 是上限。影响字节越多，穿透条件越难，Ψ 越大，该DBB贡献的距离越大。

      3.4 数据流敏感变异 (Data Flow Sensitive Mutation):

      利用效应器映射指导变异：

      • 高优先级字节： 在利用阶段，优先变异与当前种子DBBs约束相关的字节；在探索阶段，优先变异与所有约束相关的字节。
      • 值替换： 如果影响约束的输入字节是连续的，且其值与约束比较的另一个操作数不同，WindRanger会尝试用该操作数值替换这些字节，然后再进行随机变异。

      3.5 种子优先级排序 (Seed Prioritization):

      • 利用阶段： 使用两级优先级队列。(1) 为每个DBB b，找到一组能覆盖 b 的种子，并按距离从小到大排序。(2) 将每个DBB列表中的第一个种子放入高优先级（favored）队列，其余放入低优先级（less favored）队列。选择种子时，优先从favored队列选。
      • 探索阶段： 像普通CGF一样，优先选择能提高代码覆盖率的种子。
      • 能量调度： 遵循AFLGo的模拟退火算法，但使用WindRanger计算的种子距离。

      3.6 探索与利用阶段的动态切换 (Dynamic Switch between Explore and Exploit Stage):

      为了平衡探索（发现新路径）和利用（导向目标）：

      • 利用→探索： 当所有已知DBBs Φ(F) 都被“充分利用”（即被执行次数 numHit(b) > v * min_{b'∈T} numHit(b')，v为常数因子）时，切换到探索阶段。
      • 探索→利用： 当在探索阶段发现新的DBB时，切换到利用阶段。切换发生在变异完一个种子、选择新种子之前。

  2. 4 实现与评估 (4 IMPLEMENTATION & EVALUATION)

    内容：

    描述了WindRanger的实现细节和全面的评估结果，旨在回答四个研究问题（RQ）。

    • 实现： WindRanger包含静态分析器（约900行C/C++，基于SVF框架构建iCFG）和动态模糊器（基于AFL 2.52b，约1000行C代码）。

      评估设置：

      • 数据集： (1) UniBench：20个真实程序，用于评估到达目标能力（RQ1, RQ3）；(2) AFLGo Test Suite：含已知漏洞的程序，用于评估崩溃复现能力（RQ2）；(3) Google Fuzzer Test Suite：含已知漏洞的程序，也用于评估崩溃复现能力（RQ2）。
      • 对比技术： AFLGo, AFL, FAIRFuzz（选择FAIRFuzz因其也使用探测技术）。
      • 评估指标： (1) 到达目标时间（Time-to-Target, TTT）；(2) 暴露崩溃时间（Time-to-Exposure, TTE）。
      • 实验设置： 重复实验（10或20次），时间预算（24或8小时），使用Docker容器隔离，绑定单CPU核心。使用Mann-Whitney U检验和Vargha-Delaney A12统计量。

      RQ1: 到达目标能力 (Target Site Reaching Capability):

      • 方法： 在UniBench程序上选择平均首次到达时间接近5/10/15/20小时的基本块作为目标。比较WindRanger与基线到达这些目标的TTT。
      • 结果： 在大多数目标（20/24）上，WindRanger的TTT最短。平均而言，WindRanger比CGF（AFL, FAIRFuzz）快56%和55%，比DGF（AFLGo）快31%。在所有程序上，WindRanger比AFLGo、AFL、FAIRFuzz分别快21%、34%、37%。A12值（0.75对AFL/FAIRFuzz，0.67对AFLGo）表明结果具有统计显著性。

      RQ2: 漏洞复现能力 (Bug Reproducing Capability):

      • 方法： 在AFLGo Test Suite和Google Fuzzer Test Suite上，将已知漏洞点设为目标，比较WindRanger与基线暴露崩溃的TTE。

        结果：

        • AFLGo Test Suite： 对于难以触发的漏洞（TTE > 1小时），WindRanger显著优于其他工具（快1.22x到2.2x）。WindRanger在多个CVE上达到最高的命中轮次和最低的TTE。
        • Google Fuzzer Test Suite： WindRanger在11个漏洞中的9个上取得最佳TTE。平均而言，WindRanger比AFL快47%，比FAIRFuzz快59%，比AFLGo快30%。对于TTE超过1小时的漏洞，提升更大（比AFL快66%，比AFLGo快44%，比FAIRFuzz快77%）。

      RQ3: 各组件的影响 (Impact of Different Components):

      • 方法： 在UniBench目标上，分别禁用WindRanger的四个关键组件（距离计算、种子优先级排序、数据流敏感变异、探索-利用切换），评估TTT变化。
      • 结果： 禁用任何组件都会导致TTT显著增加（>10%）。数据流敏感变异贡献最大（提速22%），其次是种子优先级排序（17%）、探索-利用切换（15%）和距离计算（12%）。这证明了DBB相关组件的重要性。

      RQ4: 新漏洞发现 (New Vulnerability Discovery):

      • 方法： 安全专家将WindRanger应用于ffmpeg（已被OSS-Fuzz广泛测试）。通过人工代码审查确定50个可疑断言位置作为目标。使用WindRanger进行定向模糊测试。
      • 结果： WindRanger成功在开发分支上触发了一个断言失败，该漏洞被确认为0-day并获得CVE ID（CVE-2021-38291）。在复现此漏洞的对比实验中，WindRanger的中位TTE（8220秒）比AFLGo（13440秒）快1.64倍。

    • 作用： 通过详尽的实验设计和大规模评估（38,400 CPU小时），实证验证WindRanger的有效性和优越性，回答了关于其到达目标能力、漏洞复现能力、组件贡献和实际漏洞发现能力的核心问题。

  3. 5 有效性威胁 (5 THREATS TO VALIDITY)

    内容：

    讨论了可能影响实验结果可靠性的因素：

    内部威胁：

    • 可达性分析准确性： 静态分析（SVF）构建的iCFG可能不准确（如指针分析误差），影响潜在DBB识别。作者认为当前精度足以支撑良好性能，改进是未来工作。
  • 可配置参数： WindRanger有可调参数（如 γ, v）。作者根据经验设定，认为结果已足够好，参数调优非核心技术，留作未来工作。

外部威胁：

  • 实验设置： 工具评估存在固有不确定性。作者通过多次重复实验（10/20次）、统计检验、选择同基于AFL的基线对比、精细化的崩溃分类来缓解。

    • 作用： 客观分析研究的局限性，增强结果的可信度。

  1. 6 相关工作 (6 RELATED WORK)

    内容：

    将WindRanger与三个最相关领域的工作进行比较：

    • 定向符号执行（DSE）： 利用符号执行导向目标。指出DSE存在路径爆炸等问题，在真实程序上不如基于轻量分析的DGF（如WindRanger）有效。
  • 定向灰盒模糊测试（DGF）： 重点对比AFLGo（首个DGF）和Hawkeye（改进AFLGo）。指出它们使用所有基本块计算距离，而WindRanger聚焦于关键的DBBs。也提到其他DGF工作（如FuzzGuard的输入过滤、Leopard/Parmesan/CAFL的目标设定方法），指出WindRanger的核心贡献（DBB）可与它们互补。

    • 覆盖率导向灰盒模糊测试（CGF）： 指出CGF（如AFL）目标是最大化覆盖率，而非定向性。提到一些帮助CGF解决条件约束的技术（混合模糊Hybrid Fuzzing, Steelix, Angora, Greyone, FairFuzz），指出WindRanger在利用数据流信息（如FairFuzz/Greyone的污点）方面有相似之处，但目标不同（定向性 vs 覆盖率）。

    • 作用： 定位WindRanger在现有研究中的位置，阐明其创新点和与相关工作的区别与联系。

  1. 7 结论 (7 CONCLUSION)

    • 内容： 总结了论文的主要工作：提出了偏差基本块（DBB）的概念及其在DGF中的应用方法；设计并实现了WindRanger，利用DBB及其数据流信息增强种子距离计算、变异、调度等关键环节；通过大规模实验证明WindRanger在到达目标速度和漏洞暴露速度上显著优于现有技术（AFLGo, AFL, FAIRFuzz）；展示了WindRanger的实用性，帮助发现了ffmpeg中的0-day漏洞。
    • 作用： 凝练研究成果，重申贡献和价值。

项目分析

/instrument/sec/cbi.cpp

  • 根据用户指定的目标（源文件:行号）在调用图/控制流图上计算“距离”（函数级与基本块级），
  • 识别对到达目标有影响的“关键后继 basic block”（critical bbs）和条件点，
  • 在 LLVM IR 中插入写共享内存的指令，把距离、计数、目标标志、critical 标识与条件相关值在运行时写出，供 fuzz 驱动器（如 afl-fuzz）使用，
  • 并把修改后的 bitcode 导出为 .ci.bc 供后续编译/运行使用。

输入

bitcode/IR 目标位置

输出

  • distance.txt：每行 bb_id distance is_critical debug_info，记录为插桩而计算的 basic block id 与距离（distance 被乘以 100 并取 uint），以及是否有 critical 后继。
  • functions.txt：列出被插桩的函数 id 与位置。
  • targets.txt：对于 distance == 0（目标 basic block），记录 target_id 与 debug 信息。
  • condition_info.txt：条件（比较/strcmp）分析信息，每行包含 condition id、关联的 critical id（或 none）、操作数类型和值信息。
  • 导出的 bitcode：.ci.bc（包含注入的 distance/critical/condition 插桩）。 （这些文本产物通常会被上层脚本合并成 distance.cfg.txt 或被构建脚本用于第二次编译。）

核心流程

  1. 构建 SVF 模块与 ICFG（SVFIRBuilder），得到函数与基本块图结构。
  2. loadTargets()：读取 mytargets.txt，把 source:line 映射到 ICFG NodeID → LLVM BasicBlock，填充 targets_llvm_bb。
  3. 计算函数级距离（countCGDistance）：对每个目标做反向 BFS（ICFG fun-entry 层面），得到每个函数到该目标的步数 df；对所有目标使用谐调平均合并到 dTf[function] = 1 / sum(1/df_target)（若存在路径）。
  4. 计算基本块级距离（countCFGDistance）：函数内先将调用了有 dTf 的函数的调用点视为“pseudo-target”，设 dTb[callsite_bb] = 10 * dTf[called_func]（经验放大）；把真实目标 basic block 的 dTb 设为 0；对每个目标 basic block 做反向 BFS 得到到该目标的步数 db，并对每个 bb 用 1 / sum(1/(db + dTb[target_bb])) 合并得到最终 dTb[bb]（即把本地步数与函数级距离结合）。
  5. 识别 taint/critical：反向传播得到 taint_bbs（会影响到目标的前驱集合）；对每个有分支的 bb，如果某些后继不在 taint 集合，则这些后继视为 critical_bbs[bb]，未影响的放 solved_bbs。
  6. 插桩（instrument()）：对每个有 dTb 的 basic block 在首插入点插入 IR：
  7. 读取 __afl_area_ptr（i8*），通过 GEP 定位 MapDistLoc = MAP_SIZE（MAP_SIZE = 1 << 16 = 65536）和 MapCntLoc = MAP_SIZE + 8；
  8. 把 Distance = (uint32_t)(100 * dTb[bb]) 加到 (i64)(AFLMapPtr + MapDistLoc)（累加），并把 (i64)(AFLMapPtr + MapCntLoc) 加 1；
  9. 若 distance==0，则写 (i8)(AFLMapPtr + MAP_SIZE + 16 + target_id) = 1（标记触及目标）；
  10. 对 critical_bbs[bb] 的每个后继 cbb，在 cbb 首插入点写 __critical_bb_ptr[bb_id] = 1（或 solved 写 2），bb_id 为插桩索引；
  11. 同时在磁盘写入 distance.txt/functions.txt/targets.txt。
  12. 条件插桩（analyzeCondition() + instrumentCondition()）：
  13. 找出有意义的比较（整数 >=32位 或 小字符串比较），记录 operands 信息到 condition_info.txt；
  14. 在分支 terminator 处插入写入 __cond_map_ptr（i8）与 __cvar_map_ptr（i64）以记录分支判定和比较变量值/指针，用于运行期条件反馈。
