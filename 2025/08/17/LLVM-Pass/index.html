核心设计

四层调度颗粒

Loop / Function / CGSCC / Module

LoopPass（LoopPassManager 管）
作用域：单个函数内部的单个循环（含循环嵌套层次）。
关注点：循环规范化 (loop simplification)、展开(unroll)、分离(licm/unswitch)、向量化前置准备。
适用：需要精确迭代控制、依赖 LoopInfo / ScalarEvolution 的细粒度变换。

FunctionPass（FunctionPassManager 管）
作用域：单个函数整体（遍历所有基本块/指令）。
关注点：标量优化 (instcombine, simplify-cfg)、局部插桩、IR 规范化、函数内数据流。
适用：不需要跨函数信息、也不只针对某个循环的改写/插桩。

CGSCCPass（CGSCCPassManager 管）
作用域：调用图的一个强连通分量（SCC），即互相可递归到的一组函数。
关注点：内联(inlining)、间接调用去虚拟化、基于调用关系的 IPO（跨函数传播、函数克隆）。
适用：需要看到被调-调用关系，并且要在递归/互递归组里稳定变更（避免无限重新内联）。

ModulePass（ModulePassManager 管）
作用域：整个 Module（所有函数 + 全局变量 + 元数据）。
关注点：全局数据布局、链接期准备、跨全局分析/汇总（全局死代码清理、合并、添加全局变量/构造器、WHOLE IR 级插桩）。
适用：需要创建/删除函数、添加全局变量、扫描全局表、处理多个函数间的整体策略。

参数解析

Module &M
整个编译单元的 IR 容器，包含：函数列表（M.functions()）、全局变量（M.globals()）、目标 triple、数据布局、元数据等。
你所有“增删改”IR 的操作都针对它：新建函数/全局、修改属性、追加到 llvm.global_ctors、遍历函数插桩。

ModuleAnalysisManager &AM
分析结果（Analysis）缓存与查询入口。你当前没用它，只是忽略。
当你需要某个分析（如 TargetLibraryInfo、OptimizationRemarkEmitter、ProfileSummaryInfo 等）时，通过它拿：
auto &PSI = AM.getResult(M);
好处：按需计算 + 缓存。同一个分析多 Pass 请求只算一次，除非被之前的变换失效。
如果你对一个分析的结果仍然有效，可以在返回前：
PreservedAnalyses PA;
PA.preserve();
return PA;
否则直接返回 none()，框架会丢弃缓存
