evolvement

摘要

现有自动化软件库测试存在API误用和缺乏API序列多样性

作者提出NEXZZER 使用混合关系学习策略推断API关联关系

API误用和漏洞均可触发crash,这是模糊测试中误报的原因

这导致一个非常对立的矛盾,一方面我们尽可能希望以多样化的方式生成API调用序列以测试漏洞,又必须约束其调用,使其符合开发者规定的用法.

研究者提出两类主流的策略,第一是牺牲多样性换取准确性,通过复制现有的代码片段的调用顺序来生成测试用例,仅对API参数进行变异.

第二种则是使用更为激进的策略进行变异,但也会有大量的误报现象

简介

作者提出的NEXZZER系统实现了这两个策略的优点,高多样性和高准确性

使用新型驱动架构,通过中间API描述语言Liblang与通用解释器的协同工作实现.

此外，该系统为模糊测试器提供了动态调整变异策略的窗口，并支持隐式API关系(???)的渐进式学习

为提取隐式API关系，NEXZZER引入了创新的关系学习阶段.该阶段通过试探性变异API来观察执行状态变化，并从中推理API间关系.

将API及其关系记录至名为APIGraph的动态图结构中.将执行状态变化与变异API序列进行比对验证

在后续迭代中，模糊测试策略受APIGraph中编码的演化关系约束.

另一项贡献是自动过滤由API误用引发的误报崩溃，从而在自动化库测试中实现更高精度的结果与实用性.

通过实证方法总结判定API误用崩溃的规则集

具体来说,定义两类主要的API误用类型.参数异常和调用时序异常(UAF).基于专家经验定义多维判定规则
